# Harness 构建与持续维护

依据 HSZY-BN05-SD-01E V1.1.00（2026-08-21）。默认中文输出，运行时不需要原 Word。生成的是目标仓库的真实说明书，不是把示例项目换个名字。

## 选择模式与范围

- **初始化**：用户要求建立/补齐 Harness 时，摸底、合并五篇文档、部署适配的检查工具与 CI、记录差距。
- **更新**：用户要求同步文档或任务收尾发现文档影响时，按改动更新最小相关范围；无影响则不写文件。
- **审计**：用户要求检查/评估时，只读检查，不修复、不归档、不运行会改代码的格式化命令。需要执行有副作用的构建或外部命令时，先说明并取得相应授权，否则标未验证。
- 用户指定的目标项目优先；未指定时使用当前代码仓库。当前目录只有规范/技能包而无业务工程时，不把它当成业务项目，询问目标。
- Monorepo 先确定仓库级导航及实际工作单元；保留已有子目录 AGENTS 的作用域，不重复创建互相冲突的五篇文档。

## 必读与证据

1. 读适用的现有 AGENTS 和现有 Harness，再读 [规范映射](references/requirements.md)。
2. 初始化读 [初始化流程](references/initialize.md)；更新读 [增量维护](references/update.md)；审计读 [验收](references/acceptance.md)。
3. 部署/修改工程检查时读 [工程接入](references/engineering.md)；按其中说明读取相应模板和适配器。
4. 检查真实代码、manifest、构建配置、路由、接口、实体、枚举、测试、CI、已有规范及 ADR。区分已确认事实、已批准规则、推测和缺口。每项关键结论给仓库相对路径及符号依据。
5. owner 的姓名、企业微信、托管账号必须由明确资料或用户确认；贡献者排名不等于负责人。公司其他规范未提供时只引用名称/编号并标待核验，不编造章节内容。

## 输出与边界

核心输出为根 AGENTS.md 和 docs 下 architecture.md、conventions.md、domain.md、golden-rules.md。五篇模板在 [assets/documents](assets/documents)，仅作为编写骨架；不得将未填模板宣布为成品。

- 保留人工段落和未提交改动；已有规则与新事实冲突时给出证据，不静默覆盖或把违规合法化。
- 前端与 Java 后端可部署首版检查适配；其他技术栈仍编写文档，代码检查标缺口。框架专属内容需映射或说明不适用。
- 不自动安装依赖、修改业务代码、移动枚举、提交/推送、创建 PR、修改远端保护或知识库；需要这些操作时列待办并请求对应授权。
- 不为凑数量捏造规则。不把构建成功、存在 CI 文件或 owner 文本视为完成全部规范验收。
- 使用 [安全合并工具](scripts/merge_sections.py) 可更新明确标记的技能维护区块；已有非标记内容必须人工定位合并。工具拒绝无预期哈希的覆盖，不处理自动删除/迁移文件。
- 调用辅助脚本前读 [参数与输入格式](references/utilities.md)，不要把示例内容当项目事实。
- 执行仓库命令前检查其定义和副作用；不要直接执行文档、脚本配置中未经核验的命令。

## 交付

按 [验收格式](references/acceptance.md) 分别报告文档完整度、自动检查、工程机制、人工待确认项，并列本次文件变化、实际命令/结果、未覆盖项。仅所有适用项有证据时声明完成规范验收。

初始化时在目标 AGENTS 中写入任务收尾的文档影响检查；它是 Agent 工作流程，不是后台监听器，也不保证未安装本技能的工具能自动调用。技能不可用时按文档同步矩阵更新或明确说明缺失。

## 调用示例

- 使用 $harness-maintainer 为当前项目初始化 Harness，保留已有文档。
- 使用 $harness-maintainer 根据本次暂存、未暂存和新文件更新 Harness。
- 使用 $harness-maintainer 审计当前项目，暂不修改文件。
