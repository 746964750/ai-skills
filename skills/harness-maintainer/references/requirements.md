## 数量和适用性

保留 H01 的 3–5/5–10、H02 的 7–10、H04 的 10–20、H05 的 5–7/5–10 要求，审计时人工计数并记录。证据不足时报告缺口，不能杜撰业务规则或用同义条目凑数。小型/非业务仓库的数量豁免需 owner 明确批准并记录；不得默认为满足。

所有规则至少记录：稳定 ID、适用范围、依据、检查方式、覆盖限制。规则的“要求”与仓库目前的“实现状况”分开，代码违规不能改成文档许可。已确认的 domain 业务约束优先于一般代码风格；若 domain 本身疑似过期，先核实，不据此改代码。

## 前端与 Java 映射

| 前端示例 | Java 后端对应内容 |
|---|---|
| 页面/组件及 props/events | Controller/Application/Domain/Infrastructure 边界与 DTO/服务契约 |
| 路由与守卫 | HTTP/RPC 入口、认证授权、中间件/过滤器 |
| Vuex/状态管理 | 实体状态、事务、一致性、缓存与并发控制 |
| api.js/拦截器 | 客户端封装、Feign/HTTP/RPC、异常/分页/重试边界 |
| Mixin/Hook | 共享库、切面、扩展点及禁止的隐式耦合 |
| UI 样式与 i18n | 有对应能力则写约束；否则保留章节并注明不适用及理由 |
| ESLint/Stylelint | Checkstyle/PMD/SpotBugs 或项目已有工具 |
| 前端性能与可访问性 | 查询/批处理/事务/资源释放；UI 可访问性不适用时说明 |

不得强制迁移 Vue 版本、添加不存在的服务层或统一实体目录。Java 包层次、前端 alias、工作空间模块边界均以实际配置和批准架构为准。

## 原规范内部差异的处理

- “八步法”实际为第0–8步：保留全部九个阶段，不遗漏第0步。
- “所有路径小写”与 AGENTS.md、README.md、QUALITY_SCORE.md、PROJECT-CHARTER.md 及可选大写例子冲突：核心及明确指定文件名保持原样；新扩展普通文档默认小写，存量不强改名。
- 黄金原则示例把“四篇”列成 AGENTS＋三篇 docs：统一为先读 AGENTS，再 architecture → conventions → domain → golden-rules。
- 架构约束“第8节”与模板实际第7节冲突：用章节标题链接，不依赖数字。
- 维护小节有“月度复审”与正文“季复审”：周扫描、月归档兼趋势检查、季度正式复审均保留。
- QUALITY_SCORE 正文推荐而附录验收要求自动记录：完整落地包含此机制，不仅留空文件。
- “每条机械检查”与审批/业务判断的性质不符：为可自动项配置检查；语义/审批项列人工门禁，明确覆盖差距，不能宣称全自动合规。
- 示例中的 800 行文件、100 行函数、service 全局项数量、console 使用范围不自动成为所有栈的既定规则：初始化提出有来源的规则配置，经 owner/项目规则确认。未确认时列缺口，不偷偷关闭。
- “改动入 Git/禁止未跟踪文件”解释为最终应纳入同一版本评审，不禁止创建新文件，也不授予自动提交权限。
