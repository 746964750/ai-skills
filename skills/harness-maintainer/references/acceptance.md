# 验收与只读审计

审计模式不得修改源码、文档、配置、归档或自动格式化。结构校验可运行；执行构建/配置命令前确认副作用和授权。未经执行的检查不可记录为通过。

## 四轴报告

| 轴 | 必须报告 |
|---|---|
| 文档完整度 | H01–H07/H13/H14 的适用性、覆盖、缺口；结构通过与语义确认分开 |
| 自动检查 | 命令、扫描范围、解析器/规则版本、实际退出码、违规、错误、未覆盖规则 |
| 工程机制 | H08–H10/H12，CI 文件与远端实际生效分开；CODEOWNERS 与审批设置分开 |
| 人工待确认 | owner、业务歧义、启发式发现、H11 冷启动、知识库发布、季度复审 |

每项状态仅用：通过、失败、待确认、不适用（理由及批准依据）。文件存在、测试数量或自定义分数不是语义合规证明。任何适用必需项失败/未验证，整体为未完成验收。

初始化写 docs/harness-status.md，内容含规范版本、基线（有 Git 用 SHA＋脏状态，无 Git 标明）、证据、每项状态和缺口责任人。更新仅在状态实质变化时维护；审计默认直接在回复给报告，不落盘。

## 人工核验清单

- 逐一核对 requirements 中数量要求与每篇章节；模板标题齐全但正文空泛不通过。
- 全模块地图一致，所有枚举和合法转换有可追溯证据；没有业务状态机时说明实际用途和不适用理由。
- 指令中的路径/符号/命令真实有效；公司规范引用不杜撰。
- 架构规则与禁止事项有检查 ID、执行入口及覆盖边界；无法自动执行项保留人工审批。
- 前端/Java 检查分别注入一个违规证明能变红，再恢复为绿；只在隔离测试副本进行。
- CI 不用 continue-on-error/allow_failure/忽略退出码；全量历史违规阻断。
- CODEOWNERS 三种身份映射正确；远端 required check/review 设置由授权人验证。
- 周扫描失败仍保留报告；月归档有真实扫描来源，不编造质量分和“阅读顺序已遵守”指标。
- 三类冷启动完成并记录人员/任务/时间/结果；AI 自测不能代替新人和跨团队评审。

## 技能维护者测试

运行 python -m unittest discover -s tests -v，以及 skill-creator 的 quick_validate.py。工程适配器真实依赖不具备时可跳过对应集成测试，但必须列出跳过项；模拟命令测试不能替代真实解析器测试。行为试运行场景见 [scenario-tests.md](scenario-tests.md)。
