# Code Review

Standards 判断实现是否符合仓库规范及质量约束；Spec 判断实现是否满足已确认需求。保持独立结论，不能以一轴通过抵消另一轴缺陷。

## 1. 固定范围

读取适用的 `AGENTS.md` 与局部指引，执行必读要求。检查工作区状态，保留已有改动，不自动切分支、重置或清理文件。

按用户意图选择比较方式：

| 范围 | 比较方式 |
|---|---|
| 分支或 PR 引入的改动 | 验证引用后执行 `git diff <base>...<target>`，记录 merge-base 与目标 SHA |
| 两个版本的最终状态 | `git diff <old> <new>` |
| 单个普通提交 | `git show <commit>`；合并提交需明确父节点或比较语义 |
| 已暂存改动 | `git diff --cached` |
| 未暂存改动 | `git diff` |
| 全部未提交改动 | 检查暂存与未暂存差异，并读取 `git ls-files --others --exclude-standard` 列出的相关新文件；已有 HEAD 时用 `git diff HEAD` 辅助查看最终净变化 |

占位引用替换为真实且可解析的仓库引用。没有 HEAD 的新仓库直接审查文件及索引。基线优先采用用户指定值，其次已知 PR 目标分支；仍有多种合理解释时询问，同时开展不依赖基线的阅读。

空 diff 先核对暂存区、新文件和指定目标。确实无改动则报告“该范围无可审查差异”，不伪造通过结论。记录实际范围与命令；工作区在审查中变化时重新核对受影响部分。

## 2. 确认依据

- 按仓库指引阅读已有的 `docs/architecture.md`、`docs/conventions.md`、`docs/domain.md`、`docs/golden-rules.md` 及适用的 CONTRIBUTING、编码标准和 ADR。长文档按相关章节阅读，仓库要求全文必读时遵循要求。
- 需求优先采用用户明确提供的描述或文档，其次 PR/Issue 的明确关联，再查对应 PRD。测试和现有实现是行为证据，不自动等同于需求原文。
- `docs/agents/issue-tracker.md` 存在时可使用其中可用的访问方式，它不是前置依赖。不自动安装工具，不调用固定的外部技能初始化命令。
- 无需求源或无法访问时继续 Standards 审查，将 Spec 标为“无法完整核验”，说明缺失信息。不能从实现反推需求后宣称合规。
- 公司强制规范、项目标准和需求存在冲突时报告具体条款；个人风格和通用重构建议不算强制规则。

## 3. 双轴检查

### Standards

从 diff 追踪必要的调用方、被调用方、配置、权限边界和测试，检查正确性、兼容性、事务、并发、数据完整性及相关安全与性能风险。每个问题定位到具体触发条件，不只阅读修改行。

代码异味仅作线索：含糊命名、重复逻辑、过度依赖其他对象数据、成组参数、领域概念缺少类型、重复条件分支、散落修改、多职责模块、推测性抽象、过长调用链、纯转发层和不合适的继承。存在具体维护成本或行为影响时才报告；仓库认可的模式不因个人偏好判违规。

已有工具报告的格式或 lint 问题汇总引用，避免重复逐条发现。“可由工具检查”不等于工具已运行成功，涉及实际风险时仍需核实。

### Spec

逐项核对需求的正常、边界与失败路径，寻找遗漏、实现错误、未经要求的行为变化及兼容性破坏。每条需求缺陷附对应依据；不确定部分标为待澄清，不作为已证实缺陷。

默认当前代理完成两轴。只有运行环境允许且用户或上位指令授权委派时，才考虑独立子代理；不要求特定工具名或代理类型。最终作者负责核实与去重。

## 4. 验证与报告

对关键发现运行针对性的现有检查，或用可追踪代码路径证明影响。检查可能修改文件或外部状态时先确认副作用在授权范围内；审查请求本身不授权修复、自动格式化、推送或发布 PR 评论。

每条发现给出优先级、文件与行号、触发条件、实际影响、规范或需求依据，以及简明修复方向。区分已证实缺陷、规则违反和非阻断建议；证据不足的猜测不列为确定缺陷。

- P0：已证实的紧急阻断，例如广泛不可用或重大数据破坏风险，说明适用条件。
- P1：主要功能、权限或数据正确性问题，通常应在合并前修复。
- P2：特定场景缺陷或有明确影响的规范违反。
- P3：低影响、可选维护建议，不单独阻断合并。

按 `Standards` 和 `Spec` 分栏，各栏内部按严重程度排序。同一根因建立一个发现 ID，另一轴可交叉引用，避免重复计数。最后说明两轴独立发现数、各自最高优先级、实际检查及未覆盖范围；合并建议限定于本次证据，不等于实际合并操作。无发现时明确说明，不以“零发现”保证完整正确性。
