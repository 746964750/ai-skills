# 初始化流程

## 摸底与章程

1. 确认目标根目录、工作区状态和嵌套 AGENTS。识别前端、Java、混合或其他栈。无 Git 仍可生成，版本基线标不可用。
2. 先清点关键目录、manifest、构建脚本、CI、README、已有 Harness/ADR、模块入口/接口/实体/枚举。排除依赖、构建产物、供应商代码和密钥；排除需有理由，不能排除历史违规。
3. 结合原始需求、测试和代码梳理事实。记录模块清单及证据、读取范围、无法解析的子项目。不得声称仅抽样已覆盖全仓。
4. 编写临时 docs/PROJECT-CHARTER.md，确认定位、读者、生命周期、扩展文档、负责人三种身份信息。缺失不阻塞其他有证据内容，但阻塞最终验收。
5. 运行命令前阅读定义，区分只读检查、写缓存构建和外部/生产副作用；不为了摸底执行部署。

## 编写五篇文档

按 AGENTS 骨架 → architecture → conventions → domain → golden-rules 顺序使用 [文档模板](../assets/documents)。模板中的双花括号说明需替换成事实、具体待确认项或有理由的不适用项。不得交付未展开变量。

已存在同名文档时逐节合并，保留人写的说明、批准过的规则和用户未提交改动。不要为采用模板重命名现有章节；如保留旧标题，在检查配置 sections 中登记真实标题。先做模块清单，再复用同一事实写两处模块地图，防止数量不一致。

关键路径尽量采用 Markdown 相对链接，函数/枚举采用“文件链接＋符号名”。代码检查仅验证路径/结构，Agent 仍需核实符号及语义。外部接口仅写本项目可证明的边界，未知协议列待确认，不复制生产凭据。

将 [AGENTS 模板](../assets/documents/AGENTS.md) 中的收尾机制合并进现有约束；技能未安装时保留按同步矩阵操作的回退，不安装后台监听器。

## 工程落地与发布

读取 [工程接入](engineering.md)，明确扫描范围/规则及已有工具覆盖后部署本地脚本、配置、CI 入口、CODEOWNERS、周扫描与月归档。缺 CI 平台/owner/规则裁决时集中询问这些不可从仓库确定的信息。

工具依赖未安装时优先复用现有能力；确需新增依赖，给出原因与版本兼容证据并取得项目所需审批。不用空脚本或永远返回成功的命令占位。

按 [验收](acceptance.md) 执行检查并生成 docs/harness-status.md；首次完成后按已有 CHANGELOG 格式添加条目（不存在则创建 CHANGELOG.md），保留未完成项，不提前写“全面合规”。章程确认后注明状态、核心信息已归位，可列归档建议但不擅自删除。知识库、保护分支和人工冷启动另列待办。
